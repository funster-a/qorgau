- Ключи в `.env`: GROQ_API_KEY, TELEGRAM_BOT_TOKEN — есть. Бот создан, но новый код бота
  ещё не запускался.

**Известные грабли (не наступать повторно):**
- Порты 5432 И 5433 на этой машине заняты локальными PostgreSQL (16 и 18) → контейнер на 55432.
- Git Bash корёжит кириллицу в inline-JSON у curl → тестовые payload'ы класть в файл
  и слать `--data-binary @file` (файлы лежат в scratchpad).
- `go mod tidy` из Git Bash не видит go.mod → использовать PowerShell + `go -C <dir>`.
- При ошибке Groq тело непустое, но `choices` пуст → уже починено (проверка статуса),
  не регрессить.

**Решения:**
- Контракт API v2 зафиксирован в `docs/API.md` — фронт и бэк пишутся параллельно под него.
- Архитектура и разделение зон — `docs/ARCHITECTURE.md`.
- Бэк: агент (api/, bot/, engine/, db/). Фронт: агент (web/). Деплой+интеграция+git: оркестратор.
- Схему БД применяет сам API при старте (bootstrap) — нужно для Railway, там нет initdb.
- Подписчики бота — в зоне `pii` (chat_id — идентификатор).
- Broadcast: бот поллит /campaigns/active, а не API дёргает бота — бот единственный
  владелец TG-токена.

**Дальше:** агенты пишут код → интеграция → e2e → коммит → Railway.
